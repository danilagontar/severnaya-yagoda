# Product

## Platform

web

## Stack

React + Vite + TypeScript + Tailwind CSS v4 + shadcn/ui (решение команды). Сверка — детерминированное ядро на TypeScript (`src/core`), тесты Vitest. LLM — GigaChat API через серверный прокси, необязательно (`docs/llm.md`). Деплой — пока не решён (Vercel только с согласия пользователя).

## Users

Главный пользователь — бухгалтер «Северной ягоды» (2 бухгалтера разбирают очередь, ≈160 счетов на упаковку в месяц). Работа: к каждому счёту найти заказ, приёмку и согласование, понять расхождение, решить — платить, спросить, вернуть или остановить — и собрать платёжный реестр. Реестр утверждает финансовый директор (П-9). Заказчик — главный бухгалтер Ирина Лукина: «чтобы очередь счетов перестала расти, а мы не платили лишнего».

Вторичная аудитория — жюри Navicon AI Fest 2026: смотрит пилот на защите (до 15 минут), даёт свои письма для проверки.

## Product Purpose

Пилот, который разбирает письма из общего ящика бухгалтерии: распознаёт счёт / копию / исправление / письмо, привязывает к заказу, сверяет с согласованиями, приёмкой и арифметикой и выдаёт вердикт с суммой к оплате, причиной со ссылкой на правило и адресатом вопроса. Успех: очередь разобрана, лишние платежи не прошли, на данных кейса вердикты совпадают с эталоном 25/25.

## Positioning

Суммы и вердикты считает детерминированный код по правилам П-1…П-9, ИИ только читает свободный текст письма и формулирует письма — «ИИ не выдумывает цифры». Каждый вердикт объясним: правило, источник (ЗП, СГ, приёмка, другое письмо) и подсвеченное место в тексте. Документы проверяются вместе: письмо о реквизитах останавливает уже сверенный счёт, счета по одному заказу суммируются.

## Operating Context

Источники — выгрузка из 1С:ERP (заказы и приёмка), Directum RX (согласования), общий почтовый ящик (письма). Срез данных: 16.11.2026 12:00. Защита — показ на проекторе/ноутбуке, в том числе вставка новых писем жюри.

## Capabilities and Constraints

- 6 вердиктов: оплатить, вопрос, вернуть, дубль/заменён, стоп, письмо (контекст).
- В-13, В-21 — «вопрос» закупщику (решение команды).
- Новое письмо пересчитывает всю очередь.
- «Не платить» (135 800 ₽) и «отложено» (88 480 ₽) — разные величины, не складываются.
- Договоров (условия предоплаты) и банковской выписки в данных нет — продукт говорит об этом, а не угадывает.
- Без ключа API всё работает на правилах.

## Brand Commitments

- Никаких эмодзи в интерфейсе: вердикт = текст + значок + цвет.
- Строгий финансовый интерфейс; палитра утверждена (`docs/palette.md`): графит/нейтральные + один ягодный акцент, цвета вердиктов с проверенным контрастом. Светлая тема по умолчанию, тёмная — переключателем.

## Product Principles

1. Решение за человеком: система предлагает, бухгалтер подтверждает.
2. Каждая цифра прослеживается до источника.
3. Сначала то, что требует действия.
4. Честно показывать, чего не хватает в данных.

## Accessibility & Inclusion

Вердикт никогда не передаётся только цветом. Контраст текста ≥ 4,5 : 1 (WCAG AA).
