# Подключение LLM (GigaChat API)

## Роль LLM в пилоте

LLM делает только две вещи:
1. **Извлечение полей** из свободного текста письма: поставщик, номер счёта, номер заказа, материал, количество, единица, фасовка, цена, итог, реквизиты, тип документа (счёт / исправление / копия / письмо).
2. **Формулировка текста** письма закупщику или поставщику по готовому результату сверки.

Суммы, вердикты и выбор правила LLM не определяет никогда: это делает детерминированное ядро (`src/core`).
Ответ LLM на шаге 1 проходит ту же проверку, что и извлечение правилами: числа должны встречаться в тексте письма, иначе поле считается ненайденным.

## Режимы

| Режим | Когда | Извлечение | Тексты писем |
|---|---|---|---|
| `rules` (по умолчанию) | ключа нет | регулярные выражения и словари | шаблоны |
| `gigachat` | задан `GIGACHAT_AUTH_KEY` | GigaChat, при ошибке откат на `rules` | GigaChat, при ошибке шаблон |

Один интерфейс для обоих режимов:

```ts
interface LlmProvider {
  extract(letterText: string): Promise<ExtractedFields>;   // поля + откуда взяты (позиции в тексте)
  draftLetter(input: DraftInput): Promise<string>;           // текст письма по результату сверки
}
```

Файлы (появятся при сборке проекта):
- `src/llm/provider.ts`: интерфейс и выбор режима;
- `src/llm/rules.ts`: извлечение правилами (работает без сети);
- `src/llm/gigachat.ts`: клиент, вызывает **наш** серверный прокси, а не GigaChat напрямую;
- `server/gigachat-proxy.ts`: получение токена и запрос к модели (Node).

## Почему через серверный прокси, а не из браузера

- **Ключ авторизации секретный.** В браузерном бандле его увидит любой.
- **Сертификат.** GigaChat требует корневой сертификат НУЦ Минцифры; браузер и Node по умолчанию ему не доверяют. В Node это решается переменной `NODE_EXTRA_CA_CERTS`.
- **CORS**: пускает ли GigaChat запросы из браузера, не проверялось; прокси снимает вопрос.

## Что проверено по документации (developers.sber.ru, 12.11.2026)

- Токен: `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, заголовки `Authorization: Basic <ключ авторизации>` и `RqUID: <uuid>`, тело `scope=GIGACHAT_API_PERS` (для физлиц; бывают `GIGACHAT_API_B`, `GIGACHAT_API_CORP`). Токен живёт 30 минут.
- Ключ авторизации = Base64 от `Client ID:Client Secret`, готовый есть в личном кабинете.
- Чат: `POST https://api.giga.chat/v1/chat/completions`, тело в формате, похожем на OpenAI (`model`, `messages`, `temperature`, `functions`, `response_format`).
- Модели в документации: `GigaChat-2-Max`, `GigaChat-3-Ultra` (только физлицам во freemium).
- Без сертификата Минцифры запрос токена падает с ошибкой проверки сертификата. Сертификат: https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt (ссылка из документации Сбера).

## Проверено с реальным ключом (12.11.2026)

- Токен, запрос к модели `GigaChat-2-Max` и остаток (`GET https://api.giga.chat/v1/balance`) работают с сертификатом из `certs/`.
- Извлечение полей: два независимых разбора. правила и GigaChat читают письмо каждый сам. В карточке таблица по полям: совпало / расходится / дополнил ИИ / отклонено (числа нет в письме). Расхождение в заказе, количестве, фасовке, цене или итоге переводит счёт в «вопрос». Сверка всегда идёт по разбору правил; модель только дополняет пустые поля проверенными числами. Для новых писем сравнение запускается само, для писем кейса кнопкой «Сверить разбор с GigaChat» (чтобы не упираться в лимит запросов).
- Пример (12.11.2026): «…стоимость за штуку 4.00, к оплате 4000.»: правила не нашли цену и итог (нет «руб.»), GigaChat их дополнил, оба числа есть в тексте; на письме В-06 совпало 7 из 7 полей.
- Черновики: просьба «переписать письмо целиком» оказалась ненадёжной: модель сохраняла числа, но искажала смысл («принято и оплачено», «нет задолженности»). Поэтому ИИ пишет вступление, пояснение простыми словами и концовку **без чисел**, а приветствие, пункты с фактами, суммы, просьбу и подпись вставляет код. Ответ с цифрами или со словами вроде «оплачено», «задолженность», «штраф» отклоняется.
- Бесплатный тариф отвечает 429 Too Many Requests на частые запросы, прокси повторяет через 1,5 / 3 / 6 с.

## Расход токенов

- Каждый ответ GigaChat содержит `usage` (prompt / completion / total). Прокси копит их с запуска `pnpm dev` и пишет каждый запрос в `logs/gigachat-usage.jsonl`.
- В шапке пилота кнопка «ИИ N ток.»: сводка за сессию и остаток по моделям из `/v1/balance` (по документации доступен только при пакетах токенов).
- Ориентир по замеру: извлечение полей из одного письма ≈ 370 токенов, вступление и концовка письма ≈ 300–900.
- Полная история расхода в личном кабинете developers.sber.ru.

## Не проверено

- Работает ли GigaChat API с серверов Vercel (они за рубежом). Прокси сейчас живёт только внутри `pnpm dev`; для деплоя нужна серверная функция.

## Как включить

1. Ключ авторизации из личного кабинета → `.env.local` (см. `.env.example`), `LLM_MODE=gigachat`.
2. Сертификат Минцифры в `certs/russian_trusted_root_ca.pem` (https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt).
3. Перезапустить `pnpm dev`.

## Название в интерфейсе

В интерфейсе модель везде называется «ИИ» (без торговой марки). Какая модель подключена, видно только в `.env.local` и в этом документе.

## Демо-письма

`src/data/demo-letters.ts`: 7 писем для защиты (вкладка «Проверить пилот»), одно письмо на одну проблему: подсказка ИИ (цена без «по» и «руб.», правила её не находят), смена реквизитов, ложная тревога («реквизиты прежние»), подмена отправителя (латинская «e» и чужой домен), ошибка в итоге, дубль (опечатки в номере), другие единицы (мешки вместо кг без номера заказа). С 16.11.2026 значение, которое прочитал только ИИ, становится подсказкой в сверке: пока бухгалтер не нажмёт «Верно» или не исправит его, счёт остаётся в «вопросе».
